MINILAB 1 — LOG DE APRENDIZAJE (20/09/2026)

PUNTO DE PARTIDA
Para entender este laboratorio necesito saber qué es un archivo, cómo guardarlo y qué es un repositorio. Git trabaja con versiones de los archivos dentro del repositorio. GitHub puede guardar una copia remota, pero Git también funciona en mi computadora sin conexión a GitHub. Si clono un repositorio, obtengo una copia local y normalmente un remoto llamado origin.

DE EDITAR UN ARCHIVO A GUARDAR UNA VERSIÓN
Un cambio puede pasar por tres lugares:
1. Carpeta de trabajo: edito y guardo el archivo. git diff muestra los cambios que aún no he preparado.
2. Área de preparación: git add <archivo> selecciona la versión actual para el próximo commit. git diff --staged muestra esa selección.
3. Historial: git commit -m "mensaje" registra lo preparado en un commit local. git log --oneline permite ver el historial.

git status me dice en qué situación están los archivos. No modifica ni guarda nada. Si edito otra vez un archivo después de usar git add, esa nueva edición puede quedar sin preparar aunque la versión anterior ya esté preparada. Por eso debo consultar git status y los dos tipos de diff antes del commit.

LO QUE APRENDÍ
Editar, preparar y confirmar son acciones diferentes. git add no publica el cambio ni crea un commit. git commit tampoco lo sube a GitHub: para enviar los commits al remoto se usa git push. Git compara el contenido actual con el registrado. Si escribo una errata y la corrijo antes de confirmar, y el archivo vuelve a ser idéntico al último commit, git status ya no muestra ese cambio.

EJEMPLO PARA PRACTICAR Y EXPLICAR
Después de añadir una frase a README.md:

    git status
    git diff
    git diff --staged

La frase debería aparecer en git diff y no en git diff --staged. Después:

    git add README.md
    git status
    git diff
    git diff --staged
    git commit -m "docs: explicar los estados de un cambio"
    git log --oneline

La frase debería aparecer en git diff --staged antes del commit. Después, el commit debería verse en git log --oneline. Estos son resultados esperados del ejercicio; aún falta anotar las salidas reales.
