MINILAB 2 — LOG DE APRENDIZAJE (20/09/2026)

PUNTO DE PARTIDA
Para llegar a ramas y conflictos primero necesito dominar el MiniLab 1: saber qué es un repositorio, qué guarda un commit, cómo consultar git status y cómo preparar y confirmar cambios con git add y git commit. Un commit queda en una historia; una rama es un nombre que señala un commit de esa historia. Al hacer un nuevo commit en una rama, ese nombre avanza. Solo después de entender esto tiene sentido comparar dos ramas y fusionarlas.

RAMAS Y CAMBIO DE CONTEXTO
git switch -c propuesta crea la rama propuesta desde el commit actual y cambia a ella. git branch --show-current permite verificar dónde estoy. Si guardo un cambio en propuesta, main conserva su versión hasta que la integre. git switch main vuelve a la versión de main, siempre que mis cambios pendientes permitan cambiar de rama. Conviene ejecutar git status antes de cambiar para no confundirme con cambios sin confirmar.

FUSIÓN Y CONFLICTO
Cuando dos ramas parten del mismo commit y luego cambian, Git compara lo que aportó cada una. Si ejecuto git merge propuesta mientras estoy en main, main recibe los cambios de propuesta. La dirección importa: la rama activa es la que recibe la fusión.

En el ejercicio, las dos ramas parten de «Estado: pendiente». propuesta escribe «Estado: listo para revisión» y main escribe «Estado: aprobado en main» sobre esa misma línea. Si Git no puede elegir un resultado único, detiene la fusión y deja marcas como <<<<<<<, ======= y >>>>>>> en el archivo. Esas marcas separan las versiones en conflicto; debo elegir el texto que represente mi decisión y borrar las marcas. Una opción sería «Estado: aprobado y listo para revisión», si eso es lo que quiero expresar. git add estado.txt marca la resolución y git commit guarda la fusión. git log --oneline --graph --all --decorate permite ver cómo se unieron las historias.

LO QUE APRENDÍ
Una rama permite trabajar desde un mismo punto sin mover inmediatamente la otra rama. Un conflicto no significa que Git esté roto: significa que dos cambios requieren una decisión sobre el contenido final. Resolverlo consiste en comprender ambas versiones, editar el archivo y confirmar la solución elegida.
