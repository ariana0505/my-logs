# 08. .gitignore

`.gitignore` es un archivo de texto donde escribes **reglas para los archivos y carpetas que quieres que Git ignore mientras no estén bajo seguimiento**.

Es útil para archivos temporales, registros generados por programas y configuraciones locales que no quieres incorporar al proyecto.

## 1. Cómo se utiliza

Crea un archivo llamado exactamente `.gitignore`, normalmente en la carpeta principal del repositorio, y escribe una regla por línea. No se llama `.gitignore.md`: el archivo Markdown de este apunte solo explica su funcionamiento.

Ejemplo de contenido:

```gitignore
# Archivo de configuración local
.env

# Archivos de registro
*.log

# Carpeta de archivos temporales
temporales/

# Archivo generado por macOS
.DS_Store
```

Estas son reglas de ejemplo; añade a tu proyecto las que correspondan a sus archivos.

## 2. Entender las reglas

| Regla | Qué significa |
|---|---|
| `.env` | Ignora elementos con ese nombre dentro del alcance del archivo. |
| `*.log` | Ignora nombres que terminan en `.log`. |
| `temporales/` | Ignora carpetas llamadas `temporales` y su contenido. |
| `.DS_Store` | Ignora elementos con ese nombre. |
| `# comentario` | Es una explicación, no una regla. |

El asterisco `*` representa una secuencia de caracteres dentro de un nombre. La barra final `/` limita la coincidencia a carpetas.

Una regla como `temporales/` puede coincidir con carpetas de ese nombre en distintos niveles bajo el `.gitignore`. Si escribes `/temporales/`, se limita a la carpeta `temporales` situada directamente junto a ese `.gitignore`.

Puedes tener archivos `.gitignore` en subcarpetas; sus reglas se aplican a esa ubicación y sus descendientes.

## 3. Qué cambia en git status y git add

Si `error.log` todavía no tiene seguimiento y coincide con `*.log`:

- No aparecerá normalmente como archivo nuevo en `git status`.
- `git add .` no lo añadirá de forma predeterminada.
- Permanecerá en tu computadora: ignorarlo no significa borrarlo.

## 4. Los archivos que Git ya sigue

**`.gitignore` no deja de seguir archivos que Git ya está siguiendo.** Si registraste un archivo y después añadiste una regla para ignorarlo, Git seguirá detectando sus cambios.

Para dejar de seguir un archivo concreto conservando su copia local, puedes usar:

```bash
git rm --cached -- archivo-local.txt
```

Este ejemplo supone que `archivo-local.txt` ya tiene seguimiento y está en la ubicación indicada. Después añade su regla a `.gitignore`, revisa `git status` y registra el cambio con un commit.

`--cached` retira el archivo del área de preparación para que deje de formar parte de la próxima versión, sin borrar la copia local al ejecutar el comando. **No borra el archivo de los commits anteriores.**

## 5. Compartir las reglas

El propio `.gitignore` suele incluirse en el repositorio para que otras personas reciban las reglas al obtener el proyecto:

```bash
git add .gitignore
git diff --staged
git commit -m "chore: add ignore rules"
```

Revisa los cambios preparados antes de crear el commit, especialmente si ya habías preparado otros archivos.

## Idea principal

**`.gitignore` ayuda a mantener fuera del seguimiento archivos que no quieres registrar. No elimina archivos ni borra su historial.**
